# Spring Security: аутентификация и авторизация

Учебный проект, созданный в **мае 2023 года** для практики аутентификации и авторизации в Spring Security. В нём реализованы регистрация, вход по логину и паролю, выход из системы и разграничение доступа по ролям.

## Что изучается

- Загрузка пользователя из PostgreSQL через `UserDetailsService` и Spring Data JPA.
- Представление пользователя через `UserDetails` и работа с текущей аутентификацией.
- Хеширование паролей с помощью BCrypt и проверка пароля при входе.
- Настройка формы входа, сессии и выхода из системы.
- Роли `USER` и `ADMIN`, ограничения доступа через `@PreAuthorize`.
- CSRF-защита POST-запросов.
- Валидация регистрации и проверка уникальности имени пользователя.

При регистрации роль `ROLE_USER` назначается сервером. Пароль хранится в виде хеша и не выводится в информацию о пользователе.

## Стек

Java 17, Spring Boot 2.7.0, Spring Security 5, Spring MVC, Spring Data JPA, PostgreSQL, Thymeleaf, Maven. Для тестов используются JUnit 5, MockMvc, Spring Security Test и H2.

| Адрес | Назначение | Доступ |

| `/auth/registration` | Регистрация | Всем |
| `/auth/login` | Вход | Всем |
| `/hello` | Главная страница | USER и ADMIN |
| `/showUserInfo` | Имя и роль текущего пользователя | USER и ADMIN |

## Запуск

Нужны JDK 17, Maven и PostgreSQL. Для запуска БД через `compose.yaml` также нужны Docker и Docker Compose.

### 1. Настройка PostgreSQL

Скопируйте `.env.example` в `.env` и задайте свой локальный пароль в `DB_PASSWORD`.

```bash
cp .env.example .env
docker compose up -d
docker compose ps
```

Дождитесь статуса `healthy`. Если PostgreSQL уже установлен, вместо Docker создайте базу `security` и задайте её параметры в переменных окружения.

### 2. Переменные окружения и приложение

| Переменная | Назначение |
| --- | --- |
| `DB_URL` | JDBC-адрес БД; по умолчанию `jdbc:postgresql://localhost:5432/security` |
| `DB_USERNAME` | Пользователь БД |
| `DB_PASSWORD` | Пароль пользователя БД |

Docker Compose читает `.env` автоматически. Для приложения переменные нужно отдельно передать в окружение терминала или настроить в IDE.

Linux / macOS / Git Bash:

```bash
set -a
. ./.env
set +a
mvn spring-boot:run
```

Windows PowerShell:

```powershell
Copy-Item .env.example .env
# Задайте пароль в .env перед запуском БД.
docker compose up -d
Get-Content .env | Where-Object { $_ -match '^[A-Z_]+=' } | ForEach-Object {
    $parts = $_ -split '=', 2
    Set-Item -Path "Env:$($parts[0])" -Value $parts[1]
}
mvn spring-boot:run
```

Откройте `http://localhost:8080/auth/registration`, зарегистрируйте пользователя и войдите в систему. Таблица `person` создаётся из `schema.sql` при запуске в новой БД; Hibernate проверяет соответствие схемы сущности.

Имя пользователя: 3–50 символов, латинские буквы, цифры, точка, дефис или подчёркивание. Пароль: минимум 8 символов, максимум 72 байта UTF-8. Год рождения: от 1900 до текущего года.

### Проверка роли ADMIN

Зарегистрируйте пользователя `admin_demo`. В локальной БД назначьте ему роль:

```sql
UPDATE person SET role = 'ROLE_ADMIN' WHERE username = 'admin_demo';
```

Выйдите и войдите снова, чтобы обновить роль в сессии. Пользователь с ролью USER получает `403` при обращении к `/admin`, а ADMIN видит страницу администратора.

## Проверки

```bash
mvn test
```

Тесты используют отдельную БД H2 в памяти: PostgreSQL и переменные окружения для них не нужны. Проверяются регистрация и BCrypt, валидация, уникальность имени, запрет назначения ADMIN через форму, вход с правильным и неправильным паролем, доступ по ролям, отсутствие пароля в информации о пользователе, CSRF и выход из системы.
